## Archiving without an Xcode account (build 6 and later)

This Mac's Xcode has no Apple account, so automatic signing picks the old "iOS Team Provisioning Profile", which has no
App Groups, and the archive fails. Overriding the profile on the `xcodebuild` command line fails too: it also reaches the
Swift package resource bundles, which "do not support provisioning profiles". What works:

1. Append `PROVISIONING_PROFILE_SPECIFIER = Roll App Store 2026-11-16` to `Team.xcconfig` (project-level, so it reaches
   only Roll's own targets), and remove it again afterwards.
2. `xcodebuild archive -project Roll.xcodeproj -scheme Roll -configuration Release -destination generic/platform=iOS
   -archivePath <path> -jobs 4 CODE_SIGN_STYLE=Manual "CODE_SIGN_IDENTITY=Apple Distribution" DEVELOPMENT_TEAM=<team>`
3. `xcodebuild -exportArchive` with `method` app-store-connect, `signingStyle` manual and the same profile for
   `com.delavalom.roll`.
4. `asc publish testflight --app 6826174715 --ipa Roll.ipa --group "Roll Internal" --test-notes "$(cat
   docs/release/what-to-test-1.2-6.txt)" --locale en-US --wait`
