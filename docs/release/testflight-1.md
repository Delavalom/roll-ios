## 3. What to Test, build 1 (draft, attach at upload)

Keep it under 4,000 characters. Copy rule (ADR-0002): no performance claims, sizes are "about".

```text
First internal build. Use your own iPhone. Do destructive things (delete, squish) only inside a small album you can afford to lose, such as "Roll QA".

1. First launch and the AI model: onboarding, Photos access (try Full and Limited), taste scan. The model downloads once from Hugging Face; watch the progress, then quit mid-download and relaunch: it should pick up again. Search should work once it's ready.

2. Swipe piles (swipefiles): make one in plain words ("screenshots of tweets", "blurry"), swipe 20 or more cards, undo a few, apply. iOS must ask before anything is deleted; saying no costs nothing and keeps your free count.

3. Duplicates and Similar shots: do the groups make sense? One shot stays in each group; nothing you'd want is picked for deletion.

4. Squish: pick a big video and a big photo. The smaller copy should keep date, location, favorite and albums; the saving shown is "about" right; the original goes to Recently Deleted only after the copy is saved. HEIC photos showing as "not squishable yet" is expected.

5. iCloud honesty: with iCloud Photos and Optimize iPhone Storage on, Home should separate what is on this iPhone from what is only in iCloud. Nothing should promise space on the phone that deleting wouldn't free.

6. Paywall and trial: Annual shows a 3-day free trial, Weekly none. Start the trial (TestFlight purchases are free), check Pro unlocks, delete and reinstall, then Restore Purchases. Terms and Privacy links should open.

7. Anything else: heat or battery drain while indexing, large text sizes, wording that confuses you.

Feedback: take a screenshot in Roll and tap Share Beta Feedback, or email hi@delavalom.com.
```

## 4. Upload-day runbook

Preconditions: the model is published and Roll points at it; the D1–D5 / Part 1 device QA fixes are merged to main; the app
icon (R1) is in. One heavy process at a time on this Mac: nothing else building or converting, and at least 20 GB free
(`df -h /`; thin snapshots with `tmutil thinlocalsnapshots / 60000000000 4` if needed).

Work from a clean main checkout with the sibling `../embeddinggemma-coreml` at the commit Roll is meant to ship with.

```bash
cd ~/delavalom-labs/roll-ios
git switch main && git pull --ff-only && git status --short        # must be empty
git -C ../embeddinggemma-coreml log --oneline -1                  # the intended EG commit
test -f Team.xcconfig                                              # team id + RC_PUBLIC_KEY (don't print it)
J=~/.local/share/mise/shims/just
```

**Step 1. Build number.** Check the next number ASC accepts:

```bash
asc builds next-build-number --app 6826174715 --platform IOS --output json
```

- Build 1 (first upload): nothing to change; `App/Info.plist` already says version 1.0, build 1.
- Build 2 and later: first land the A3 fix (`CFBundleVersion: $(CURRENT_PROJECT_VERSION)`,
  `CFBundleShortVersionString: $(MARKETING_VERSION)`, `MARKETING_VERSION: "1.0"` in `project.yml`), then set
  `CURRENT_PROJECT_VERSION` to the number above in `project.yml`, commit on a branch, merge. Never edit `Roll.xcodeproj`.

**Step 2. Release check** (does its own `just gen` and an unsigned Release build, about 2 GB):

```bash
$J release-check        # must print PASS and exit 0; exit 1 = finding, exit 2 = harness problem (not a pass)
$J test                 # RollCore unit tests green
```

**Step 3. Archive.**

```bash
$J gen
asc xcode archive --project Roll.xcodeproj --scheme Roll --configuration Release --clean \
  --archive-path build/tf/Roll.xcarchive \
  --xcodebuild-flag=-destination --xcodebuild-flag=generic/platform=iOS \
  --xcodebuild-flag=-allowProvisioningUpdates --output json
```

Sanity-check the archive's plist (no secrets printed):

```bash
P=build/tf/Roll.xcarchive/Products/Applications/Roll.app/Info.plist
/usr/libexec/PlistBuddy -c "Print :CFBundleShortVersionString" -c "Print :CFBundleVersion" \
  -c "Print :ITSAppUsesNonExemptEncryption" "$P"                       # 1.0 / N / false
test -z "$(/usr/libexec/PlistBuddy -c 'Print :RCTestStoreKey' "$P" 2>/dev/null)" && echo "Test Store key empty"
test -n "$(/usr/libexec/PlistBuddy -c 'Print :RCPublicKey' "$P" 2>/dev/null)" && echo "RC public key present"
```

**Step 4. Export** (App Store Connect method, automatic signing; creates the distribution cert and profile on first run):

```bash
asc xcode export --archive-path build/tf/Roll.xcarchive --ipa-path build/tf/Roll.ipa \
  --xcodebuild-flag=-allowProvisioningUpdates --output json
asc ipa-info --path build/tf/Roll.ipa --include-entitlements --verify-signature --output json
# expect bundle com.delavalom.roll, an Apple Distribution signer, the sensitivecontentanalysis entitlement
```

If export says there is no signing certificate: Xcode → Settings → Accounts → the team → Manage Certificates → + Apple
Distribution, then rerun step 4.

**Step 5. Upload, attach to the internal group, add What to Test** in one command (internal group only, so no beta
review; never add `--submit`):

```bash
asc publish testflight --app 6826174715 --ipa build/tf/Roll.ipa \
  --group "Roll Internal" --test-notes "$(cat build/tf/what-to-test.txt)" --locale en-US \
  --notify --wait --timeout 60m --output json
```

(`build/tf/what-to-test.txt` = the block in section 3.) Equivalent split form, if you want to look between steps:

```bash
asc builds upload --app 6826174715 --ipa build/tf/Roll.ipa --wait
BUILD_ID=$(asc builds list --app 6826174715 --build-number N --platform IOS --output json | python3 -c 'import sys,json; print(json.load(sys.stdin)["data"][0]["id"])')
asc builds test-notes create --build-id "$BUILD_ID" --locale en-US --whats-new "$(cat build/tf/what-to-test.txt)"
asc builds add-groups --build-id "$BUILD_ID" --group fcd188be-2c05-4bc9-bcc2-bafc24ed336a
asc testflight notifications send --build-id "$BUILD_ID"
```

**Step 6. Confirm it's testable.**

```bash
asc status --app 6826174715 --until testflight-ready --timeout 60m --output json   # READY_FOR_BETA_TESTING / IN_BETA_TESTING
asc testflight groups list --build-id "$BUILD_ID" --output table                   # shows Roll Internal
```

`MISSING_EXPORT_COMPLIANCE` here means the plist key didn't make it into the build (check step 3's output), not that a
declaration is needed.

**Step 7. Install.** On the founder's iPhone: TestFlight app → Roll → Install. Delete any Xcode-installed Roll first, or
the QA database and Debug state get mixed up (TestFlight replaces the Debug build; same bundle id).

**Step 8. Smoke pass** against the What to Test list, in the "Roll QA" album only for anything destructive.

**Step 9. Trial purchase test.**

a. TestFlight (the real test for TF1), on the founder's own Apple Account:

1. Fresh install from TestFlight, go through onboarding to the paywall (or Settings → Roll Pro).
2. Check the Annual plan shows the 3-day free trial and USD 29.99/year after it; Weekly USD 4.99, no trial.
3. Start the trial. The sheet says it's a TestFlight/sandbox purchase and no charge happens. Pro unlocks right away.
4. RevenueCat dashboard → Customers, with "sandbox data" on: one customer with an active `pro` entitlement, trial period,
   product `roll_pro_annual`, store App Store, environment sandbox.
5. Delete the app, reinstall from TestFlight, tap Restore Purchases: Pro comes back.
6. Manage it in iOS Settings → Apple Account → Subscriptions (TestFlight subscriptions show there and renew on a
   compressed schedule; exact timings differ from production). Cancel to watch the expiry path.
7. That Apple Account has now used its trial: later TestFlight installs show no trial, which is the correct eligibility
   behavior, not a bug.

b. Repeatable trial tests (optional, needs the sandbox tester from P11): build a development build without the local
StoreKit file (`$J run-device`, which uses `xcodebuild build`, not the Xcode Run action), install it, sign in under
Settings → Developer → Sandbox Apple Account, buy, and between runs clear the history with
`asc sandbox clear-history --id SANDBOX_TESTER_ID --confirm`.

**Step 10. Record it.** Add the build number, upload date and smoke/trial results to `docs/qa/` and tick M9 in
`docs/MILESTONES.md` once the build is processed and installed.
