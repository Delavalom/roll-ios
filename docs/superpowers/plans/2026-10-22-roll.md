# Roll Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a native iOS 18+ photo-cleanup app with on-device EmbeddingGemma 2 search: swipefiles, duplicates, squish (compression), a device monitor, and a RevenueCat Pro subscription. Shipped to internal TestFlight.

**Architecture:** a SwiftUI app shell over a local SwiftPM package `RollCore`, which holds one target per core module (Library, Indexer, Signals, Store, Ranking, Dedupe, Squish, Monitor, Entitlements, Embedding). Each module is unit-tested on macOS or the simulator without the app. The real embedder comes from `../embeddinggemma-coreml/swift` behind the `Embedder` protocol; `StubEmbedder` is used for tests and previews.

**Tech stack:** Swift 6, SwiftUI, Observation, PhotoKit, Vision, SensitiveContentAnalysis, AVFoundation, ImageIO, Accelerate, BackgroundTasks, LocalAuthentication, Swift Charts, GRDB 7, RevenueCat `purchases-ios` 5, XcodeGen, Swift Testing, XCUITest, `just`, `asc`.

**Spec:** `docs/superpowers/specs/2026-10-22-roll-design.md`. Read it first.

### Task 2: Embedding protocol and stub

**Files:** `Sources/Embedding/{Embedder.swift,StubEmbedder.swift,GemmaEmbedder.swift}`, `Tests/EmbeddingTests/StubEmbedderTests.swift`.

```swift
// Embedder.swift
import CoreGraphics
public protocol Embedder: Sendable {
  var dimensions: Int { get }
  var revision: String { get }
  func embed(image: CGImage) async throws -> [Float]
  func embed(query: String) async throws -> [Float]
}
```

- `StubEmbedder` is deterministic. The image vector is a hash of a 16×16 grayscale downsample projected into `dimensions` with a seeded matrix, then normalized. The query vector is a hash of the lowercased words projected the same way. Its tests: identical input gives an identical vector, the output is normalized, and two different images give cosine < 0.99.
- `GemmaEmbedder` wraps `EmbeddingGemma` (`load(.huggingFace(repo: EmbeddingGemma.defaultRepo, revision: EmbeddingGemma.defaultRevision), budget: .auto, dimensions: 256)`). Until s7 publishes, `defaultRepo` points to a local `file://` source: debug builds read `EGCM_MODEL_PATH` from the environment and fall back to `Bundle.main` if the developer copied the model in.
- [ ] Write the tests → run them (fail) → implement → run (pass) → commit `feat(core): embedder protocol + stub`.

### Task 3: Store (GRDB schema, repositories, vector store)

**Files:** `Sources/Store/*`, `Tests/StoreTests/{SchemaTests,RepositoryTests,QuotaTests}.swift`.

- [ ] **Schema** (migration `v1`):

```sql
CREATE TABLE asset (
  id TEXT PRIMARY KEY, mediaType INTEGER NOT NULL, subtypes INTEGER NOT NULL, created REAL, pixelW INTEGER, pixelH INTEGER,
  duration REAL, isFavorite INTEGER NOT NULL DEFAULT 0, burstId TEXT, uti TEXT, estBytes INTEGER NOT NULL DEFAULT 0,
  cloudOnly INTEGER NOT NULL DEFAULT 0, embedded INTEGER NOT NULL DEFAULT 0, signalsDone INTEGER NOT NULL DEFAULT 0,
  blur REAL, aesthetic REAL, isUtility INTEGER, sensitive INTEGER, phash INTEGER, featurePrint BLOB, deleted INTEGER NOT NULL DEFAULT 0);
CREATE INDEX asset_created ON asset(created);
CREATE INDEX asset_phash ON asset(phash);
CREATE TABLE swipefile (
  id TEXT PRIMARY KEY, name TEXT NOT NULL, kind TEXT NOT NULL, preset TEXT, prompts TEXT NOT NULL, examples TEXT NOT NULL DEFAULT '[]',

CREATE TABLE decision (
  swipefileId TEXT NOT NULL REFERENCES swipefile(id) ON DELETE CASCADE, assetId TEXT NOT NULL, verdict TEXT NOT NULL,
```

- [ ] **Records:** Codable structs `AssetRecord`, `SwipefileRecord` (`prompts`/`examples` as JSON text; `classifier` as `Data` = 257 little-endian floats), `DecisionRecord` (`verdict ∈ {action, keep, album}`).
- [ ] **`Repositories`:**

  - `markDeleted(ids)`;
  - `decisions(for:)`, `record(decision)`, `undo(swipefileId, assetId)`, `queued(for:)` (where applied = 0 and verdict ≠ keep);
  - `markApplied`.
- [ ] **`VectorStore`:** an actor wrapping `EmbeddingIndex.VectorIndex` at `Application Support/Roll/vectors.egix`. `open(revision:)` catches `.revisionMismatch`, deletes the file, resets `asset.embedded = 0` for all rows, and reopens.
- [ ] **`FreeQuota`** (in `Entitlements`, using the `quota` table): `static let limit = 50`; `remaining()`; `consume(n) throws(QuotaError.exceeded)`.
- [ ] **Tests:** migration on an in-memory DB; upsert/pending ordering; decision undo; quota consumption to 50, after which the 51st throws; VectorStore revision reset (using a temp dir).

### Task 4: Signals

**Files:** `Sources/Signals/*`, `Tests/SignalsTests/*` (fixture images taken from `../embeddinggemma-coreml/fixtures/images` and copied into `Tests/SignalsTests/Resources/`: 2 sharp, 2 blurry, 1 screenshot, 2 near-duplicates).

- [ ] **`BlurScore.score(cgImage) -> Float`:** grayscale 256-px max side via vImage, Laplacian 3×3 convolution (`vImageConvolve_PlanarF` with kernel [0,1,0,1,-4,1,0,1,0]), then the variance. Test: the blurry fixtures score < 0.5 × the sharp ones.
- [ ] **`PerceptualHash.dHash(cgImage) -> UInt64`:** a 9×8 grayscale difference hash. `hamming(a,b)`. Test: near-dup pairs ≤ 10 bits apart, unrelated pairs ≥ 20.
- [ ] **`FeaturePrints.compute(cgImage) async throws -> Data`** (raw floats: `"FP01"`, UInt32 LE count, Float32 LE values) with `decode(Data) -> Print?` and `distance(Data, Data) -> Float` (squared L2, equal to Vision's `distance(to:)`), using the iOS 18 Swift Vision API `GenerateImageFeaturePrintRequest(.revision2)` (`FP01` means revision 2; a new revision needs a new magic). Test: near-dup distance < 0.35 < unrelated distance.
- [ ] **`Aesthetics.compute(cgImage) async throws -> (overall: Float, isUtility: Bool)`** via `CalculateImageAestheticsScoresRequest`. Test: the screenshot fixture has `isUtility == true` on the iOS 18 simulator. The test is marked `.enabled(if: Aesthetics.isSupported)`, because the macOS test host may not support it.
- [ ] **`Sensitive`:** `SCSensitivityAnalyzer`; returns nil if `analysisPolicy == .disabled`.
- [ ] **`SignalExtractor.extract(cgImage) async throws(CancellationError) -> AssetSignals`** combines all the above. A failing signal leaves only its own fields nil; the only error is cancellation, so the Indexer never commits half-cancelled signals. Feature print and aesthetics share one `ImageRequestHandler` (with per-request fallback), the sensitivity check runs beside them, and `refreshPolicy()` is called once per batch.
- [ ] TDD → commit `feat(core): vision signals`.

### Task 5: Library and size estimation

**Files:** `Sources/Library/*`, `Tests/LibraryTests/SizeEstimatorTests.swift`.

- [ ] **`SizeEstimator.estimate(mediaType:pixelW:pixelH:duration:uti:fps:) -> Int64`:**
  - HEIC images: px × 0.35; JPEG: px × 0.9; PNG: px × 1.6.
  - Videos: `duration × bitrate(short side, fps)`, where bitrate (bits/s) is 2160p 45M, 1080p@60 18M, 1080p 10M, 720p 5M, other 2.5M, divided by 8. Tiers use the short side, so portrait clips match. PhotoKit has no frame rate: fps is 60 when the `videoHighFrameRate` subtype is set, else 30.
  - Tests cover each branch with exact expected integers.
- [ ] **`PhotoLibrary`** (iOS only):
  - `authorization() async -> PHAuthorizationStatus` (requests `.readWrite`);
  - `fetchAll() -> [AssetSnapshot]` (newest first; images + videos; **no UTI**, for speed at 50k assets) and `utis(for:)`, called only for ids new to the Store;
  - `thumbnail(id:, side:, allowNetwork:) async -> ThumbnailResult` (`.image`, `.inCloud` or `.failed`; cancellation-safe; upright pixels) and a batched `thumbnails(ids:side:allowNetwork:)` (`PHImageManager.requestImage` with `deliveryMode = .highQualityFormat`, `resizeMode = .fast`, `isSynchronous = false`, `isNetworkAccessAllowed`);
  - `videoFrame(id:, at:) async -> ThumbnailResult` (`AVAssetImageGenerator` at 10% of the duration).
- [ ] **`AssetSnapshot`** is a plain struct built from a PHAsset: id, mediaType, subtypes raw, created, pixel size, duration, favorite, burstIdentifier. `uti` is nil when built from a `PHAsset`; `PhotoLibrary.utis(for:)` fills it from the original resource (`.photo` / `.video`, else the first) for ids new to the Store.
- [ ] **`ChangeObserver`** wraps `PHPhotoLibraryChangeObserver` and yields `AsyncStream<LibraryChange>` with `inserted`, `removed` and `changed` ids (favorites matter to the keeper) plus `requiresResync` when PhotoKit has no incremental details. Single-use; stream termination unregisters.
- [ ] TDD for SizeEstimator → commit `feat(core): library + size estimates`.

### Task 6: Indexer and scheduler

**Files:** `Sources/Indexer/*`, `Tests/IndexerTests/IndexerTests.swift`.

- [ ] **The `Indexer` actor**, with init(`library: LibrarySource`, `embedder: Embedder`, `signals: SignalSource`, `repo`, `vectors`, `thermal: ThermalGate`). `LibrarySource` and `SignalSource` are protocols, so tests inject fakes.
  - `func sync() async throws`: fetch all snapshots (`uti` is nil) → for ids the Store already has, keep the stored UTI (`upsertAssets` uses `uti = COALESCE(excluded.uti, asset.uti)`); for ids new to the Store, fetch `utis(for:)` and merge them in → compute estBytes with SizeEstimator (after the UTI merge) → upsert records → mark missing ids deleted.
  - `func run(limit: Int? = nil, progress: @Sendable (Int, Int) -> Void) async throws`: loop over `pendingAssets(limit: 200)`. For each asset:
    1. `await thermal.waitUntilOK()`;
    2. load the thumbnail (960 px; for videos, the frame); if it's nil and the asset is cloud-only, set `cloudOnly = 1` and skip;
    3. extract signals and the embedding in parallel (`async let`);
    4. `vectors.upsert`.

    Save cadence: every **200** assets the Indexer commits signals with `repo.commitSignals` (it never touches `embedded`). Every **2,000** assets, on background or expiry (`BGProcessingTask` expiration, `scenePhase` change) and at the end of a run, it flushes embeddings in this order: `vectors.upsert` (batch) → `vectors.save()` → `repo.markEmbedded(ids:)`, so a flag never claims a vector the file doesn't have (`VectorStore.reconcile()` repairs any leftover on open). Because the two calls touch disjoint columns, re-embedding after a model change keeps all Vision signals. It checks `Task.isCancelled` between assets and flushes before returning.
- [ ] **`ThermalGate`:** waits while `ProcessInfo.processInfo.thermalState.rawValue >= ThermalState.serious.rawValue`, polling every 5 s. The thermal state provider is injectable.
- [ ] **`IndexScheduler`:** registers `BGProcessingTaskRequest(identifier: "com.delavalom.roll.index")` with `requiresExternalPower = true` and `requiresNetworkConnectivity = false`. The handler runs `indexer.run()` with cancellation tied to the `expirationHandler`. It reschedules on app background if pending > 0.
- [ ] **Tests:** a fake library with 450 assets, StubEmbedder, and fake signals:
  - after `run`, all are embedded and 3 batch commits happened;
  - a thermal fake that is `.serious` for the first 2 polls delays without failing;
  - cancellation mid-run leaves the processed rows committed and the rest pending.
- [ ] TDD → commit `feat(core): indexer with thermal gate and background scheduling`.

### Task 7: Ranking (presets, scorer, classifier, engine)

**Files:** `Sources/Ranking/*`, `Tests/RankingTests/{LogisticClassifierTests,ScorerTests,SwipefileEngineTests}.swift`.

- [ ] **`LogisticClassifier`:** `train(x: [[Float]], y: [Float], weights: [Float], l2: Float = 1e-2, iters: 200, lr: 0.5) -> (w: [Float], b: Float)` with full-batch gradient descent using vDSP (`vDSP_mmul` for the logits); `prob(x)`.

  Test: on 2 Gaussian clusters in 256-d (seeded), training accuracy is > 0.95 and it runs in < 50 ms in release.

```swift
@Test func separatesClusters() {
  var g = SeededRNG(seed: 3)
  let pos = (0..<20).map { _ in (0..<256).map { _ in Float.random(in: 0.2...1, using: &g) } }
  let neg = (0..<20).map { _ in (0..<256).map { _ in Float.random(in: -1 ... -0.2, using: &g) } }
  let m = LogisticClassifier.train(x: pos + neg, y: Array(repeating: 1, count: 20) + Array(repeating: 0, count: 20),
                                   weights: Array(repeating: 1, count: 40))
  let acc = (pos.map { m.prob($0) > 0.5 ? 1 : 0 }.reduce(0, +) + neg.map { m.prob($0) < 0.5 ? 1 : 0 }.reduce(0, +))
  #expect(Double(acc) / 40 > 0.95)
}
```

  (`SeededRNG` is a SplitMix64 `RandomNumberGenerator` in `Tests/RankingTests/SeededRNG.swift`.)
- [ ] **`Presets`:** an enum `screenshots, blurry, memes, receipts, privateStuff, bigVideos`. Each case has:
  - `name`;
  - `prompts` (spec §5 table: memes = ["a meme with caption text", "a reaction image", "an internet meme"]; receipts = ["a photo of a receipt", "a photo of a document", "a whiteboard"]; private = ["a nude photo", "an intimate private photo", "a photo in underwear"]; screenshots = ["a screenshot of a phone screen"]; blurry = ["a blurry out of focus photo"]; bigVideos = []);
  - `candidateFilter(AssetRecord) -> Bool`: screenshots = subtypes & `photoScreenshot` (1 << 2); blurry = blur < `BlurScore.threshold` (25.0) || aesthetic < −0.3; receipts = isUtility == 1 || true (embedding decides); private = true; bigVideos = mediaType == video && estBytes > 50 MB; memes = mediaType == image;
  - `signalBoost(AssetRecord) -> Float`: screenshots +1 if subtype; blurry +(1 − blur/threshold) clamped; receipts +0.3 if isUtility; private +0.5 if sensitive == 1;
  - `defaultAction`: bigVideos → squish, else delete.
- [ ] **`Scorer.score(vector:, swipefile:, promptVectors: [[Float]], exampleVectors: [[Float]], record:) -> Float`:**
  - with a classifier: prob(v) + boost;
  - otherwise: max cos over prompts + 0.5 × mean cos over examples (0 if none) + boost.
  - Tests use hand-built vectors (exact arithmetic expectations).
- [ ] **`SwipefileEngine`** (actor) with `candidates(for swipefile, limit: 20) async throws -> [Candidate]`:
  1. cached prompt vectors through `embedder.embed(query:)`;
  2. iterate `vectors` over all embedded, non-deleted assets that pass the filter and have no decision yet;
  3. score, apply the floor (0.2 untrained, 0.5 trained), return the top `limit` by score;
  4. `bigVideos` (no prompts) ranks by estBytes.

  `record(verdict:)` stores the decision and increments `swipesSinceTrain`. It (re)trains when the swipefile has ≥ 8 decisions with ≥ 2 of each label and `swipesSinceTrain >= 5` (or no classifier yet): positives = action/album, negatives = keep, plus prompt vectors as positives with weight 2. It persists the classifier.

  Tests use StubEmbedder plus an in-memory store with 100 synthetic assets: no repeats after a decision; training triggers at the right count; `undo` removes the decision.
- [ ] TDD → commit `feat(core): ranking + learning swipefiles`.

### Task 8: Dedupe

**Files:** `Sources/Dedupe/*`, `Tests/DedupeTests/*`.

- [ ] **`DuplicateGrouper.groups<P>(records: [AssetRecord], window: 120, fpThreshold: 0.35, prepare: (Data) -> P?, distance: (P, P) -> Float) -> [[String]]`** (plus a convenience overload `distance: (Data, Data) -> Float` for tests). `window`, `fpThreshold`, `nearPhashDistance` (4) and `maxNeighbors` (24) are public static constants. `prepare` decodes a stored print lazily, at most once per record; the Indexer/app path passes the real decoder, so no print is decoded per pair.
  1. Sort by created, then id.
  2. Link records sharing a `burstId` directly.
  3. Sliding window: compare each record with at most `maxNeighbors` successors created within `window`; link when the print distance < threshold or `hamming(phash) <= 4`. This bounds distance calls at `n * maxNeighbors`.
  4. Global exact pass: bucket by phash and link hamming 0. Degenerate hashes (0, `.max`, popcount ≤ 4 or ≥ 60) are skipped. A bucket of more than 8 members links only pairs whose prints are both present and closer than `fpThreshold`.
  5. Union-find → components of size ≥ 2, ordered by total estBytes descending (then member count, then first id).
- [ ] **`KeeperPolicy.keeper(group) -> String`:** favorite > highest aesthetic > largest pixel count > newest.
- [ ] **Tests:**
  - synthetic records with injected distances: 3 shots 30 s apart with distance 0.2 make one group; the same shots 10 minutes apart make no group unless the phash matches exactly;
  - keeper ordering cases.
- [ ] TDD → commit `feat(core): duplicate grouping`.

- [ ] **Tests:** generated MOV → squished: smaller, same duration ± 0.1 s, metadata location item present. Generated JPEG (4000×3000 noise + gradient) → HEIC: smaller, GPS dictionary equal.
- [ ] **`ReplaceFlow`** (library calls behind an internal seam; the PhotoKit implementation is iOS only). Requires full library access (`needsFullAccess` otherwise). Two steps, so the user sees one system prompt:
  1. `prepare(items, progress:) async -> PrepareReport`, per item: refuse ineligible assets (typed `IneligibilityReason`: edited, multi-resource, burst, spatial/depth/Live/animated, not in the user's library, multi-frame, `unsupportedFormat` for anything but JPEG/PNG photos and ProRes/Log/Dolby Vision videos); check free space (2x source + 500 MB, again with the real exported size); export the original (cancellable download) and check it decodes at the asset's size; squish (HEIC keeps the HDR gain map and aux data and every metadata key; video keeps audio, timed metadata, bit depth and colour); journal the item; create the new asset with date, location, favorite, hidden state and user-album membership (`shouldMoveFile`); verify the copy as stored (exact size, one resource of the expected type, size and SHA-256 read back, metadata fingerprint). Originals are never touched. Progress phases: downloading, encoding, verifying, saving.
  2. `commitDeletes([Prepared]) async throws -> SquishCommitResult`: one `performChanges` that re-reads each pair inside the block (`CommitGuard`: modification date unchanged, still eligible, fingerprints still match) and deletes only the originals that pass; the rest are `skipped` with a reason. `userCancelled` throws `.userDeclinedDelete` (copies and originals remain; `retryDelete` or `discardCopies` recover). A second commit changes nothing.
  3. `reconcile()` on launch settles the Store journal (`squishJournal`, migration v4): pending verified pairs, orphan copies, finished rows.

  Savings are *estimated* (`SquishCommitResult.estimatedSavings`, `recentlyDeletedPending = true`): space is only freed once Recently Deleted is emptied or after 30 days. `transferLimitations` lists what can't be carried over (captions, keywords, people tags, shared-album membership, the Shared Library disclosure) for the confirm sheet. Background time is requested per item through an injected `BackgroundExecution` hook (no UIKit in the package; the adapter ends the task in its expiration handler and `end` is idempotent); expiry cancels the current item cleanly, stops the batch and removes scratch files. Cover the pure parts and the flow (via a fake library with real per-asset state) with unit tests, and PhotoKit writes with the device QA checklist in `docs/MILESTONES.md` M6.
- [ ] **`SquishPlanner.plan(records:keep4K:)`:** candidates with at least `minimumSavingsFraction` (30%) estimated savings, each with its `Downscale` (4K to 1080p) so the UI can say so. The HEVC bitrate target is resolution x fps x 0.07 bits per pixel, clamped to 1.5...25 Mbps, and never planned above the source bitrate.
- [ ] TDD → commit `feat(core): squish (video HEVC, photo HEIC, metadata-preserving replace)`.

### Task 11: Commit planner and committer

**Files:** `Sources/Commit/{CommitPlanner.swift,PhotoKitCommitter.swift,SquishRunner.swift}`, `Tests/CommitTests/*`.

- [x] **`CommitPlanner.plan(queued: [DecisionRecord], records: [String: AssetRecord], swipefiles: [String: SwipefileRecord], isPro: Bool, quotaRemaining: Int) -> CommitPlan`** (pure). The swipefiles say what `.action` means (delete / album / squish) and which album an up-swipe (`.album`) goes to: `albumName`, else the swipefile's name, else "Roll". `CommitPlan` is `{deletes: [String], albumMoves: [String: [String]], squishes: [SquishRequest], estBytes: Int64, blockedByQuota: Int, settles: [CommitOperation: [DecisionKey]], stale: [DecisionKey]}`:
  - decisions in `decidedAt` order (ties: swipefile id, asset id); `.keep` and applied ones ignored;
  - per asset, a delete supersedes album moves and squishes (and settles their decisions); album moves and a squish of one asset both run;
  - if not Pro, distinct assets past `quotaRemaining` are blocked, in order of each asset's first decision (quota counts assets, not decisions);
  - decisions whose asset is deleted or unknown are `stale`: nothing to apply, settled for free;
  - `estBytes` sums the deletes' estimates only (squish savings come from `SquishPlanner`).
- [x] **`PhotoKitCommitter.apply(plan, progress:) async throws -> CommitOutcome`** (`.applied(CommitReport)` or `.cancelled(CommitReport)`; named so it doesn't clash with Squish's `CommitResult`). PhotoKit sits behind an internal `CommitLibrary` seam, so ordering, chunking, cancel and quota are unit-tested on macOS with a fake library and a real in-memory Store. Order:
  1. plain deletes in chunks of 500 per `performChanges` (one iOS confirmation per chunk, the minimum);
  2. album moves, one `performChanges` per album (sorted by title): find the regular user album with that title, or create it, then `addAssets`;
  3. squishes through a `SquishRunner` (below): `prepare` the whole batch with progress, then `commitDeletes` once, its own prompt, because Squish verifies every copy first.

  Declining the first prompt therefore applies nothing. After each change succeeds, `Repositories.recordApplied` marks its decisions applied and its deleted assets deleted in one transaction, then `FreeQuota.consumeUpTo` spends quota for the distinct assets it changed (not Pro). A user cancel (`PHPhotosError.userCancelled`, `SquishRunnerError.userDeclinedDelete`, or task cancellation) stops the run and returns `.cancelled`: the declined change and everything after it cost nothing; changes confirmed before it stay recorded. A declined squish prompt leaves the copies in `pendingSquishCopies` (`retrySquishDeletes(_:of:)` or `discardCopies`). Other errors throw `CommitFailure` carrying what already happened. If the quota ran out in the meantime (a race), `consumeUpTo` still uses up the remainder, so the next plan shows it as used.
- [x] **`SquishRunner`** (in Commit, so the committer compiles and tests without the Squish target) mirrors `ReplaceFlow`'s batch API: `prepare([SquishRequest], progress:) async -> SquishBatch`, `commitDeletes([SquishedCopy]) async throws -> SquishDeletion`, `discardCopies([String])`. Without a runner, squishes stay queued (`squishUnavailable`).
- [ ] Squish now provides `ReplaceFlow` (`SquishCommitResult`, skipped items with reasons, `needsFullAccess`, `reconcile()`): a small adapter conforms `ReplaceFlow` to `SquishRunner` (`SquishItem` gets the "Keep 4K" choice; `ReplaceError.userDeclinedDelete` → `SquishRunnerError.userDeclinedDelete`; `verificationFailed` copies → `leftoverCopyID`).
- [x] TDD → commits `feat(commit): ...`.
