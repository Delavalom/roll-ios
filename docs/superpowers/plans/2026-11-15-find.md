# Plan: Roll finds things too (trips, activities, living albums, memory videos) (2026-11-15)

People use Ask Roll to find the photos from a trip or an activity, make an album of them, and then make a "together"
video of the trip somewhere else. This plan makes that path accurate and short, measures it on a real library, and
markets it next to cleanup. Executed end to end in one session (founder, 2026-11-15).

Inputs: ADR-0005 (Ask Roll search), `docs/investigations/2026-10-29-pile-eval.md` (the only search eval so far:
cleanup queries, proxy labels), `docs/investigations/2026-10-29-search-and-piles-results.md` (phone numbers), DigUp
(github.com/ARahim3/DigUp, MIT: ideas only, write our own code).

## Where search stands (measured 2026-10-29, iPhone 13 Pro Max, ~29.7k items)

- **Speed is fine.** Typed search 24–29 ms warm, query embedding included.
- **Accuracy is not measured for finding things.** `evals/piles.json` has cleanup queries only.
- **Answers are too big to make an album from.** z >= 2 passes 3–5 % of any library (434–1,623 strong matches per
  query, ~32 % precision on cleanup queries). Nonsense got 890.
- **No place.** The store keeps `created`, not location.
- **Album is a side path.** An Ask answer is a delete pile; an album is the up-swipe (`CommitPlanner`).

## How accuracy is measured (the find eval)

- **Data**: the phone's current Roll database and vector index (copied from the app container, read-only), plus a
  QA export from the phone: per asset `created`, location, media type, album membership; album titles; optional
  Apple Vision scene labels (to measure whether they'd help); 256 px thumbnails on request.
- **Queries** (`evals/find.json`): ~30 the way people search: activities (soccer, gym, hiking, swimming), events
  (birthday, wedding, concert, graduation, Christmas), places and trips (beach, snow, a city or country from the
  library, "trip to X 2024"), things (dog, food, car, sunset, flowers), plus album-derived queries (one per trip or
  activity album) and the 12 nonsense strings from `evals/piles.json`.
- **Labels**: album members are relevant for that album's query. Everything else is **pooled judging** (TREC-style):
  each variant's top 50 per query, unioned, rendered as numbered contact sheets, judged relevant / not by a vision
  model from thumbnails. A second round judges new results that later variants bring in.
- **Metrics** per query and variant: P@10, P@20, P@50, nDCG@20, pooled recall@100, answer size (strong + weaker),
  nonsense refused (yes/no), latency on the Mac. Means over query groups. Output:
  `docs/investigations/evidence/2026-11-15-find-eval/*.json` (no ids), note `docs/investigations/2026-11-15-find-eval.md`.
- **Variants** (all in RollCore so the app runs the same code):
  - V0 today: `PhotoSearch.rank` (z >= 2, fused words, fold 0.4).
  - V1 query template: embed "a photo of {q}" (and template ensembles) instead of the bare query.
  - V2 query understanding: date words ("last summer", "2024", "June", "Christmas", "this year") and place words
    (gazetteer) become filters; the rest is embedded.
  - V3 events: library grouped into events (time gap + distance); an event's support (how many strong matches it holds)
    lifts its photos, stray hits drop; "rest of this day" expansion.
  - V4 Vision labels fused like words (only if the export shows they help; costs a Vision pass per photo).
  - V5 more like these: 3 picked relevant results become image seeds (photo-to-photo cosine) blended with the query.
  - Nothing found: a top-cosine / top-z floor tuned on nonsense + absent queries.
- The best combination ships; thresholds go in an ADR (ADR-0006) with the numbers.

## Data contracts

- Private root: `~/egcm-evidence-raw/2026-11-15/find/` (`db/roll.sqlite`, `index/vectors.egix`, `export/assets.jsonl`,
  `export/albums.json`, `export/vision.jsonl`, `thumbs/`, `pools/`, `sheets/`, `labels/`).
- `assets.jsonl` line: `{"id","created","lat","lon","hacc","mediaType","subtypes","albums":[albumKey]}` (lat/lon null
  when absent).
- `albums.json`: `[{"key","title","count"}]`, user albums only (Roll-made ones included).
- `vision.jsonl` line: `{"id","labels":[["identifier",confidence]]}` for confidence >= 0.1, top 10.
- Thumb request: `Documents/qa/find/thumb-request.txt` (one id per line) → `thumbs/<id-sha1-prefix>.jpg`, 256 px.
- Labels: `labels/<query-slug>.json` = `{"relevant":[id], "notRelevant":[id]}`.
